Работай сначала только как архитектор и аналитик. Пока не пиши код приложения, не устанавливай зависимости и не создавай исполняемый файл.

Полностью прочитай:
- `AGENTS.md`
- `docs/tz-seyfy-novy-proekt.md`
- `docs/APPROVED_ARCHITECTURE.md`
- `data/cell_heights.csv`
- `reference/seyfy-prototip.html`

Важное утверждённое решение: каждый сотрудник запускает собственный локальный экземпляр приложения, а две SQLite-базы лежат на общем сетевом диске. Обычно работает один сотрудник, редко одновременно до трёх. Не заменяй это решение центральным сервером. Твоя задача — корректно спроектировать реализацию в этих рамках.

Сделай следующее:

1. Проверь требования на противоречия и неясности, кроме уже утверждённой сетевой архитектуры.
2. Подробно спроектируй:
   - read-only соединения `mode=ro` для просмотра;
   - короткие write-транзакции только по подтверждённым действиям;
   - `BEGIN IMMEDIATE`, `busy_timeout`, rollback и повторную проверку состояния;
   - запрет WAL;
   - уникальную защиту от двух активных договоров одной ячейки;
   - безопасную работу с рабочей и архивной базой через `ATTACH DATABASE`;
   - поведение при потере сетевого пути;
   - SQLite Backup API и хранение 30 комплектов;
   - контролируемое, а не автоматическое восстановление.
3. Проверь формулы дней, продления, штрафа и все граничные даты.
4. Проверь модель хранения персональных данных и технических логов.
5. Проверь `cell_heights.csv`: количество строк, уникальность номеров, допустимые высоты, пропуски и дубликаты.
6. Создай или обнови только документацию:
   - `docs/DECISIONS.md`;
   - `docs/OPEN_QUESTIONS.md`;
   - `docs/DATA_MODEL.md`;
   - `docs/IMPLEMENTATION_PLAN.md`;
   - `docs/ACCEPTANCE_TESTS.md`;
   - `docs/TRACEABILITY.md` — соответствие «раздел ТЗ → модуль → тест».
7. Раздели реализацию на небольшие этапы. Для каждого укажи входные условия, файлы, тесты и критерий готовности.
8. Не додумывай банковские поля документов. Неясные реквизиты вынеси в `OPEN_QUESTIONS.md`.

В конце покажи:
- краткое резюме архитектуры;
- обнаруженные противоречия;
- риски, которые остаются из-за сетевого диска, без попытки отменить утверждённое решение;
- созданные или изменённые файлы;
- вопросы владельцу продукта;
- точный следующий промпт для первого этапа реализации.
