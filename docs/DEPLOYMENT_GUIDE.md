# Развёртывание переносимой версии

## Что устанавливается

Установщика нет. На каждом рабочем компьютере находится своя локальная копия папки `safe-cells-portable`; Python, Node.js и доступ в интернет сотруднику не нужны. На сетевом диске общими остаются только две базы, `templates`, `backups`, `damaged-originals` и служебные файлы блокировок.

`safe-cells.exe` нельзя запускать с сетевого диска. Локальный EXE открывает сервер только на `127.0.0.1`, автоматически выбирает свободный порт и открывает браузер по умолчанию. Один компьютер не слушает подключения от других компьютеров.

## Сборка

Проверенная среда: Windows 10, Python 3.14.6, PyInstaller 6.21.0. Точные версии всех использованных пакетов записаны в `requirements-lock.txt`.

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m pytest -q -W error
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_portable.ps1
.\.venv\Scripts\python.exe .\scripts\smoke_test_portable.py
```

Последняя команда копирует один EXE в изолированную временную папку, убирает Python из `PATH` дочернего процесса и проверяет полный цикл: запуск, health, выбор сотрудника, калькулятор, открытие, DOCX, продление, закрытие, журнал, Excel, резервные комплекты и завершение своего процесса.

Результат сборки: `dist\safe-cells-portable`. `build` и `dist` не коммитятся.

## Подготовка общей тестовой папки

1. Используйте отдельную папку на том же типе SMB-хранилища и с теми же правами, что будут в работе, но только с вымышленными данными.
2. Оба файла `vault_cells.sqlite3` и `vault_archive.sqlite3` должны находиться в этой одной папке и на одном томе.
3. Рядом должен существовать каталог `templates` с шестью утверждёнными DOCX.
4. Первичную инициализацию или миграцию выполняйте один раз с административного компьютера из исходников. Обычный EXE никогда не создаёт и не обновляет схему автоматически.
5. Фактический UNC-путь храните только в локальных `config.json`; не добавляйте его в Git, документы или технические логи.

Если общие базы имеют схему 5, перед запуском новой сборки закройте все экземпляры приложения и один раз выполните:

```powershell
.\.venv\Scripts\python.exe -m app.cli migrate-v6 --config config.local.json --confirm MIGRATE-TO-6
```

Команда сначала создаёт проверенный резервный комплект обеих баз, затем добавляет телефон и поля напоминаний без удаления старых договоров. Старые договоры останутся без телефона, пока сотрудник не заполнит его через редактирование.

Если базы уже имеют схему 6, перед запуском сборки со схемой 7 закройте все экземпляры приложения и один раз выполните:

```powershell
.\.venv\Scripts\python.exe -m app.cli migrate-v7 --config .\config.local.json --confirm MIGRATE-TO-7
```

Миграция сначала создаёт согласованную резервную копию обеих баз. Существующие 126 ячеек получают состояние «действует»; договоры и архивные записи не удаляются.

Если базы имеют схему 7, перед запуском сборки со схемой 8 закройте все экземпляры приложения и один раз выполните:

```powershell
.\.venv\Scripts\python.exe -m app.cli migrate-v8 --config .\config.local.json --confirm MIGRATE-TO-8
```

Миграция сначала создаёт согласованный резервный комплект. Существующие тарифы получают ширину и глубину из `vault_defaults`, ручные штрафные ставки переводятся на полный размер; договоры, продления, архив и журнал не удаляются.

Если базы имеют схему 8, перед запуском сборки со схемой 9 закройте все экземпляры приложения и один раз выполните:

```powershell
.\.venv\Scripts\python.exe -m app.cli migrate-v9 --config .\config.local.json --confirm MIGRATE-TO-9
```

Миграция сначала создаёт согласованный резервный комплект, затем добавляет небольшой реестр отменённых открытий и продлений. Существующие договоры, продления, архив и журнал не изменяются.

Если базы имеют схему 9, перед запуском сборки со схемой 10 закройте все экземпляры приложения и один раз выполните:

```powershell
.\.venv\Scripts\python.exe -m app.cli migrate-v10 --config .\config.local.json --confirm MIGRATE-TO-10
```

Миграция сначала создаёт согласованный резервный комплект, затем расширяет реестр отмен возможностью безопасно отменить закрытие. Существующие строки отмен, договоры, продления, архив и журнал сохраняются.

Если базы имеют схему 10, перед запуском сборки со схемой 11 закройте все экземпляры приложения и один раз выполните:

    .\.venv\Scripts\python.exe -m app.cli migrate-v11 --config .\config.local.json --confirm MIGRATE-TO-11

Миграция сначала создаёт согласованный резервный комплект, затем добавляет необязательный ID клиента АБС к активным и закрытым договорам. Все старые данные сохраняются.

Если базы имеют схему 11, перед запуском сборки со схемой 12 закройте все экземпляры приложения и один раз выполните:

    .\.venv\Scripts\python.exe -m app.cli migrate-v12 --config .\config.local.json --confirm MIGRATE-TO-12

Миграция создаёт резервный комплект, добавляет второй телефон и настройку длительности сеанса АБС. Старые договоры и архив сохраняются.

## Подготовка рабочего компьютера

1. Скопируйте папку `safe-cells-portable` в постоянную локальную папку компьютера.
2. Один раз запустите `configure-database.cmd`.
3. В открывшемся окне выберите общую папку, в которой непосредственно находятся `vault_cells.sqlite3`, `vault_archive.sqlite3` и каталог `templates`. Не выбирайте отдельный файл или родительскую папку.
4. Мастер проверит обе непустые базы и шесть утверждённых шаблонов, затем сам создаст корректный UTF-8 `config.json`. Вручную вводить путь и редактировать JSON не требуется. При повторной настройке прежний конфиг сохраняется как `config.previous.json`.
5. От имени обычного пользователя один раз запустите `create-shortcut.cmd`.
6. Убедитесь, что на рабочем столе появился ярлык «Сейфовые ячейки».
7. Запустите ярлык: консольного окна быть не должно, браузер должен открыться автоматически, а при входе — показать карточки активных сотрудников и администратора. При первой настройке администратор вводит своё ФИО и создаёт простой пароль.

Для обновления приложения закройте все его вкладки, убедитесь, что локальный процесс завершён, затем замените локальную папку новой проверенной сборкой. После замены снова запустите `configure-database.cmd` и выберите ту же общую папку; не переносите фактический сетевой путь в Git.

## Приёмка на 1–3 компьютерах

Выполните на тестовой сетевой папке с вымышленными данными:

- одновременно откройте приложение на одном, двух и трёх компьютерах;
- убедитесь, что каждый браузер использует собственный адрес `127.0.0.1` и свой порт;
- на одном компьютере обновите страницу: процесс не должен завершиться;
- оставьте вкладку в фоне минимум на две минуты, затем вернитесь и обновите её: страница должна остаться рабочей на том же локальном адресе;
- откройте журнал второй вкладкой, закройте главную: журнал должен продолжить работу;
- закройте последнюю вкладку одного компьютера: завершается только его локальный процесс, остальные продолжают читать и записывать;
- одновременно попробуйте занять одну свободную ячейку: успешным должен остаться только один договор;
- выполните открытие, продление, закрытие, скачивание DOCX и Excel;
- проверьте новый полный резервный комплект после каждой записи;
- временно отключите тестовый сетевой путь и убедитесь, что старая сетка скрыта, а пустая локальная база не создаётся;
- после восстановления сети перечитайте состояние, не повторяя неопределённую запись автоматически;
- отдельно, при закрытых остальных экземплярах, повторите контролируемое восстановление только на тестовых копиях;
- проверьте EXE штатным антивирусом/Windows Defender на каждом типе рабочего компьютера;
- визуально откройте все пять сформированных DOCX в используемой версии Microsoft Word.

## Критерий допуска

Автоматические тесты и локальная переносимая проверка не заменяют конкретный SMB-том, права пользователей, антивирус и Microsoft Word. Производственный допуск возможен только после заполнения листа ниже ответственным сотрудником:

| Проверка | Результат/дата |
|---|---|
| 1 компьютер, тестовый SMB |  |
| 2 компьютера одновременно |  |
| 3 компьютера одновременно |  |
| конфликт одной ячейки |  |
| отключение/возврат сети |  |
| резервные комплекты |  |
| тестовое восстановление |  |
| Windows Defender/антивирус |  |
| пять DOCX в Microsoft Word |  |
| решение ответственного о допуске |  |

До заполнения этого листа приложение технически собрано, но не объявляется принятым для производственной работы банка.
