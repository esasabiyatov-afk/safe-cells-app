# Принятые и предлагаемые решения

Статусы: **утверждено** — уже закреплено исходными документами; **на согласовании этапа 0** — безопасное техническое решение, которое вступит в силу после одобрения плана.

| ID | Статус | Решение | Причина |
|---|---|---|---|
| D-001 | утверждено | У каждого сотрудника свой локальный Flask-процесс; две SQLite-базы общие на сетевом диске. | `APPROVED_ARCHITECTURE.md`. |
| D-002 | утверждено | Чтение — короткое `mode=ro`; запись — `BEGIN IMMEDIATE`, DELETE journal, FULL synchronous, NORMAL locking и таймаут 15 секунд. WAL запрещён. | Безопасность сетевой SQLite. |
| D-003 | утверждено | Операции двух баз выполняются через `ATTACH DATABASE` и один `COMMIT`; бэкапы — через SQLite Backup API, последние 30 комплектов. | Исключение частичных изменений. |
| D-004 | на согласовании этапа 0 | Канонические источники находятся в `docs/`, `data/`, `reference/`; совпадающие файлы в корне считаются исходными дубликатами и не используются кодом. | Исключение расхождения копий. |
| D-005 | уточнено решением D-055 | Статус ячейки не хранится в `cells`: договорная занятость означает наличие строки в `contracts`; `contracts.cell_number` имеет `UNIQUE`. | Один источник истины для договорной аренды. |
| D-006 | на согласовании этапа 0 | Backend независимо пересчитывает и проверяет дни, тариф и суммы перед сохранением, хотя frontend показывает мгновенный предварительный расчёт. | Backend-проверки обязательны; браузер можно подменить. |
| D-007 | на согласовании этапа 0 | Внутренние идентификаторы договора и операции — UUID; повтор той же операции определяется по `operation_id`. | Безопасная проверка неопределённого результата сети и защита от двойного нажатия. |
| D-008 | утверждено 12.07.2026 | Единственная валюта приложения — сом (`KGS`); выбора валюты в формах нет. Все суммы целые, без дробной части, `float` не используется. Начальный залог — 1500 сом и редактируется администратором рядом с тарифами. | Прямое решение владельца требований; исключение лишнего поля и ошибок округления. |
| D-009 | на согласовании этапа 0 | Поиск по ФИО/счёту выполняется коротким запросом на backend и возвращает номера совпавших ячеек; общий список не передаёт персональные поля. | Полное скрытие данных важнее полностью клиентского поиска. |
| D-010 | на согласовании этапа 0 | Любая бизнес-запись вместе с аудитом меняет обе базы одной транзакцией через `ATTACH`. | Журнал не должен отставать от рабочего состояния. |
| D-011 | на согласовании этапа 0 | DOCX готовится во временный файл до транзакции, а публикуется после `COMMIT`; сбой публикации не отменяет сохранённый договор. | Файловую операцию нельзя включить в SQLite-транзакцию. |
| D-012 | на согласовании этапа 0 | Производственные базы создаются только отдельной административной командой; обычный запуск требует существующие валидные файлы. | Запрет пустой локальной или сетевой подмены. |
| D-013 | на согласовании этапа 0 | Основной стек: стандартный `sqlite3`, Flask, pytest, библиотека DOCX на соответствующем этапе и PyInstaller на этапе сборки; ORM и frontend-сборка не нужны. | Малый автономный стек и прозрачный SQL. |
| D-014 | на согласовании этапа 0 | Технические логи обезличены; полный аудит изменений хранится только как бизнес-данные в архивной БД. | Совместить расследование изменений и запрет утечки ПДн в технические логи. |
| D-015 | на согласовании этапа 0 | Настройки шаблонов хранят только относительные имена; DOCX лежат в общей папке `templates`. | Одинаковые шаблоны у всех сотрудников и переносимость UNC-пути. |
| D-016 | на согласовании этапа 0 | Даты хранятся в ISO, статусы и расчёты получают дату явно; временные метки аудита содержат смещение часового пояса. | Повторяемые тесты и однозначный аудит. |
| D-017 | на согласовании этапа 0 | Начальный порог статуса «истекает» равен 7 дням и редактируется администратором. | Значение 7 показано в визуальном референсе; изменение обратимо и не влияет на деньги или срок договора. |
| D-018 | утверждено 12.07.2026 | Сотрудник запускает приложение веб-ярлыком на рабочем столе. Ярлык скрыто запускает локальный `.exe` и открывает браузер; статический HTML без backend не используется. | Прямое решение владельца требований; сохраняет безопасную работу с SQLite без ручного запуска `.exe`. |
| D-019 | утверждено 12.07.2026 | Цвета статусов должны иметь усиленный контраст, заметные границы и цветную полосу внутри плитки. | Офисные мониторы могут передавать близкие пастельные оттенки недостаточно различимо. |
| D-020 | утверждено 12.07.2026 | Залог показывается отдельно и не складывается с суммой аренды. Объединённая строка «Итого к оплате» в калькуляторе не используется. | Прямое уточнение владельца требований; залог не должен восприниматься как часть стоимости аренды. |
| D-021 | утверждено технически 12.07.2026 | Персональные данные активного договора выдаются только отдельным POST-запросом с временным токеном текущего запуска, номером ячейки и точным идентификатором ожидаемого договора. | Защищает от случайного общего раскрытия, межсайтового запроса и подмены договора при конкурентном изменении. |
| D-022 | утверждено 12.07.2026 | Если продление оформлено до или в дату текущего окончания, новый период начинается на следующий день после него. Если продление оформлено позже, новый период начинается в фактическую дату продления. Произвольное перекрытие периодов запрещено. | Прямое решение владельца требований; однозначно определяет даты нового периода и штрафа. |
| D-023 | утверждено 12.07.2026 | Дата начала нового активного договора не может быть позже текущей даты приложения. Backend сверяет её с серверной датой при расчёте и повторно внутри write-транзакции; уже сохранённая активная запись с будущим началом считается ошибкой целостности, а не получает обычный статус. | Прямое уточнение владельца требований; будущий активный договор невозможен и не должен искажать статус ячейки. |
| D-024 | утверждено 12.07.2026 | При досрочном закрытии оплаченная аренда за неиспользованные дни не возвращается и приложением не пересчитывается. Отдельной функции произвольных удержаний из залога нет. При причине «Потеря ключа» залог не возвращается; в остальных сценариях приложение показывает полный залог к возврату. | Прямое решение владельца требований; исключает лишние денежные функции и фиксирует единственное специальное правило потери ключа. |
| D-025 | утверждено 12.07.2026 | На общей сетке занятой ячейки показываются фамилия и инициалы клиента, а в оперативной карточке — такое же краткое имя. Полное ФИО и остальные персональные данные остаются в закрытом блоке. Плитки увеличены и сделаны прямоугольными; высота показана в правом нижнем углу без «мм». | Прямое решение владельца требований и явное исключение из прежнего запрета передачи любого ФИО в общий список. |
| D-026 | утверждено 12.07.2026 | Из карточки убраны первоначальный тариф, первоначальная сумма аренды, залог и пояснение о штрафе. Финансовые значения сохраняются для расчётов и архива, но не создают визуальный шум. При непросроченном продлении или закрытии штрафные сведения полностью скрыты; штрафная ставка не показывается в интерфейсе. | Прямое решение владельца требований; вычисления и аудит сохраняются без лишней детализации интерфейса. |
| D-027 | заменено решением D-032 | Номер договора и дата выдачи ID-карты были удалены из форм, API и схем обеих баз. | После проверки реального банковского шаблона выяснилось, что дата выдачи обязательна; номер договора по-прежнему не возвращается. |
| D-028 | утверждено 13.07.2026 | В карточке занятой ячейки полное ФИО показывается сразу после отдельного защищённого запроса и не дублируется в раскрываемом блоке. Общий срок выводится без первоначального срока. На главном экране есть «Свободно» и общий счётчик «Занято», внутри которого показано разбиение на «В норме», «Истекает» и «Просрочено». Заголовок приложения — «Депозитарий», организация — ЗАО АКБ «Толубай». | Прямые уточнения владельца требований; полный список ячеек по-прежнему получает только фамилию с инициалами. |
| D-029 | утверждено 13.07.2026 | Сводка по статусам размещается внутри центральной части верхней шапки; отдельная полоса над рабочей областью не используется. Легенда состоит из простых зелёного, синего, жёлтого и красного квадратов. ФИО на плитках уменьшено относительно номера и размера ячейки. | Прямые визуальные пометки владельца требований на согласованном снимке экрана. |
| D-030 | уточнено решением D-032 | Обычное редактирование разрешает исправлять только ФИО, номер, орган и дату выдачи ID-карты, а также номер счёта. Даты аренды, тарифы, суммы и залог через эту форму не меняются. Старые и новые значения записываются в бизнес-аудит одной транзакцией с активным договором. | Безопасный белый список выполняет ТЗ по исправлению ошибок без скрытого изменения денег и срока. |
| D-031 | утверждено технически 13.07.2026 | До получения банковских DOCX механизм проверяется только на шаблонах и данных с явной пометкой «ТЕСТОВЫЙ». Шаблон берётся по активной записи `document_templates` и безопасному имени внутри общей папки `templates`; результат атомарно публикуется в локальные «Загрузки», без реестра файлов. | Не создаёт ложных юридических документов и исключает выход за утверждённые каталоги. |
| D-032 | утверждено 13.07.2026 | Дата окончания ID-карты заменяется датой выдачи в формах, API и обеих базах. Переход схемы 2→3 выполняется только явной командой, после согласованного бэкапа двух баз и одной транзакцией через `ATTACH DATABASE`. | Владелец требований подтвердил, что прежнее удаление даты выдачи было ошибкой; поле требуется реальному договору. |
| D-033 | заменено решением D-044 | При первом запуске каждой Windows-учётки приложение один раз запрашивало полные фамилию и имя сотрудника и запоминало соответствие локально на компьютере. | Владелец требований отказался от связи сотрудника с Windows-учёткой. |
| D-034 | утверждено 13.07.2026 | Для открытия формируются `Акт приема передач сейф.docx`, `Договор индивидуального сейфа ф.л.docx`, `Распоряжение Открытие сейф.docx`; для продления — `Доп. соглашение сейф ф.л.docx`; для закрытия — `Распоряжение Закрытие сейф.docx`. Первый реальный шаблон использует 18 утверждённых кодов в квадратных скобках. | Прямое решение владельца требований и проверка приложенного договора. |
| D-035 | утверждено 13.07.2026 | `[Договор.НачалоД]` и `[Договор.НачалоДК]` берут первоначальную дату из `contracts.start_date`. Коды `[Продление.Начало]`, `[Продление.Конец]`, их кыргызские варианты, `[Продление.Сумма]` и `[Продление.Срок]` берут данны конкретной строки `renewals`. В переданном DOCX после `[Договор.НачалоДК]` уже напечатано `-жылдагы`, поэтому значение кода заканчивается годом без второго дефиса. | Прямо утверждённые владельцем коды; контекстный суффикс проверен в реальном шаблоне. |
| D-036 | утверждено 13.07.2026 | Исправленный `Договор индивидуального сейфа ф.л.docx` использует 18 ранее утверждённых кодов. В дополнительном соглашении строки `Паспорт:` используют `[Клиент.Документ.Номер]`. Параметры страницы основного договора сохраняются без изменения: верхнее 1,5 см, нижнее 1,1 см, левое 2,5 см, правое 1,5 см. | Исправленные файлы и снимок параметров страницы от владельца требований. |
| D-037 | утверждено 13.07.2026 | В распоряжении на закрытие цифровая и прописная суммы залога подставляются отдельными кодами `[Залог.Цифр]` и `[Залог.Пропись]`. Все пять файлов утверждённого комплекта формируются автоматически после успешного сохранения соответствующего действия: три при открытии, один при продлении и один при закрытии. | Исправленный файл и ранее утверждённый состав комплекта D-034. |
| D-038 | утверждено технически 13.07.2026 | Явная команда `init-db` регистрирует только те пять утверждённых шаблонов, которые уже находятся в общей папке `templates`. Ошибка DOCX после `COMMIT` не отменяет сохранённое бизнес-действие: сотрудник получает отдельное предупреждение и не должен повторять само открытие, продление или закрытие ради документа. | Не держит SQLite write-lock во время обработки DOCX и не допускает автоматического повтора операции с неопределённым исходом. |
| D-039 | утверждено технически 14.07.2026 | Административный пароль хранится как версионированный `scrypt`-хеш с отдельной случайной солью. После пяти неверных попыток локальный процесс блокирует вход на 15 минут; токен успешного входа живёт 20 минут только в памяти процесса и не записывается в браузерное хранилище или БД. | Выполняет требование стойкого хеша, ограничивает перебор и не создаёт нового файла с секретом. |
| D-040 | утверждено технически 14.07.2026 | Администратор может менять `expiring_soon_days`, `deposit_amount_minor` и ставки полного набора тарифов. Валюта, масштаб и границы периодов в интерфейсе неизменяемы, а backend всё равно проверяет полный непрерывный набор для фактических высот. DOCX принимается только после проверки размера, структуры и известных полей. | Белый список и повторная backend-проверка защищают денежные правила и юридические шаблоны от подмены браузера. |
| D-041 | утверждено владельцем 14.07.2026; заменяет D-039 в части входа | В настройках выбирается один из двух режимов: единый пароль отдела либо предупреждение без пароля с обязательной отметкой руководителя. Блокировки неверных попыток и автоматического истечения доступа нет; технический токен живёт только в памяти процесса до закрытия окна. В парольном режиме сохраняется только `scrypt`-хеш с солью. | Приложением пользуется один отдел в доверенной внутренней среде; владелец явно выбрал простую модель доступа при сохранении обязательной защиты хранения пароля. |
| D-042 | утверждено владельцем 14.07.2026 | DOCX может не содержать полей: такой шаблон считается готовым статическим документом и копируется без заполнения. Интерфейс показывает назначение, имя и наличие файла, список полей и позволяет получить исходную копию. | Поддерживает печать документов без автоматического заполнения и делает фактическое использование шаблонов понятным. |
| D-043 | утверждено владельцем 14.07.2026 | Изменение тарифной сетки не пересчитывает финансовые условия уже открытых договоров и сохранённых продлений. Каждое новое продление рассчитывается по тарифу, действующему в момент подтверждения, и сохраняет собственные ставку, сумму и штраф неизменяемым снимком. | Исторические договорные условия не должны меняться задним числом; дополнительное соглашение заключает новые условия по актуальному тарифу. |

## Разрешённые безопасные уточнения

- На дату окончания договор ещё не просрочен: при остатке 0 дней статус `expiring`.
- Порог «истекает» включителен: при пороге 7 остаток ровно 7 дней относится к `expiring`.
- Номер ячейки хранится как текст, чтобы не закрывать путь будущим форматам, но seed использует значения `1`–`126`.
- Ширина 220 мм и глубина 330 мм находятся в единственной строке `vault_defaults`; индивидуальные значения в `cells` остаются `NULL`, пока не требуется исключение.
