# Утверждённая архитектура проекта

Этот документ содержит согласованные изменения к исходному ТЗ и имеет приоритет при противоречии.

## 1. Способ запуска

- На рабочем столе каждого сотрудника находится веб-ярлык «Сейфовые ячейки».
- Сотрудник запускает только ярлык. Он без консольного окна запускает собственный локальный экземпляр `safe-cells.exe` из папки установки и открывает интерфейс в браузере.
- Обычный статический HTML-файл не используется как приложение: браузер не должен напрямую читать или изменять общую SQLite-базу.
- Внутри экземпляра запускается локальный Flask-сервер на свободном порту.
- Интерфейс автоматически открывается в браузере сотрудника.
- Закрытие вкладки или выход из программы влияет только на локальный экземпляр этого сотрудника.

## 2. Общие базы на сетевом диске

- `vault_cells.sqlite3` и `vault_archive.sqlite3` размещаются в одной общей папке на сетевом диске банка.
- Обычно приложением пользуется один сотрудник; редко одновременно — до трёх сотрудников.
- Путь к общей папке задаётся конфигурацией.
- Если путь недоступен, приложение показывает ошибку и не создаёт локальную замену.

## 3. Чтение

- При обычном просмотре приложение открывает SQLite URI-соединение с `mode=ro`.
- Выполняет нужные `SELECT`-запросы и сразу закрывает соединение.
- Соединение не остаётся открытым между запросами пользователя.
- Главный экран обновляется после запуска, после изменений, вручную и автоматически примерно раз в 15 секунд.

## 4. Запись

Read/write-соединение открывается только после явного подтверждения операции, которая меняет данные.

Алгоритм:

1. Открыть короткое соединение.
2. Установить `foreign_keys=ON`, `busy_timeout=15000`, `journal_mode=DELETE`, `synchronous=FULL`, `locking_mode=NORMAL`.
3. Выполнить `BEGIN IMMEDIATE`.
4. Повторно проверить актуальное состояние данных.
5. Выполнить изменения.
6. Выполнить `COMMIT`, а при ошибке — `ROLLBACK`.
7. Закрыть соединение в любом случае.
8. Перечитать данные.
9. Создать резервную копию.

Не изменять файловый атрибут Windows «Только чтение». Read-only и read/write — это режимы SQLite-соединений.

## 5. Одновременная работа

- WAL запрещён.
- Одновременно выполняется только одна короткая операция записи.
- Вторая операция ожидает до 15 секунд, затем получает понятную ошибку без изменения данных.
- Перед созданием договора состояние ячейки повторно проверяется внутри транзакции.
- `contracts.cell_number` защищён уникальным ограничением.

## 6. Рабочая и архивная база

- Обе базы находятся в одной папке и на одном томе.
- Связанные изменения двух баз выполняются через `ATTACH DATABASE` в одной транзакции.
- При закрытии договора архивная запись и журнал создаются до удаления активного договора, но все действия фиксируются только общим `COMMIT`.

## 7. Бэкапы и повреждение

- Не заменять активную базу временным файлом после каждой записи.
- Бэкап создавать через SQLite Backup API после успешного `COMMIT`.
- Хранить последние 30 комплектов.
- Не выполнять автоматическое восстановление, пока другие экземпляры могут работать.
- При повреждении запретить запись и запустить контролируемую процедуру восстановления администратором.

## 8. Потеря сети

- При ошибке чтения показать ошибку доступа к сетевому диску.
- При неопределённом результате записи не повторять действие автоматически.
- После восстановления сети сначала проверить фактическое состояние базы.
