# Приёмочные и автоматические проверки

## 1. Общие правила тестов

- Используется `pytest` и временные локальные каталоги.
- Реальные сетевые пути и персональные данные запрещены.
- Дата передаётся в функцию явно; прямой `datetime.now()` в тестируемой бизнес-логике не используется.
- Тесты проверяют состояние обеих баз после успеха и после ошибки.
- Производственный `busy_timeout` равен 15000 мс; тест может подставить меньший таймаут, сохраняя тот же путь обработки.
- Успешная команда и точное число тестов записываются в `PROJECT_STATUS.md` после каждого этапа.

## 2. Матрица обязательных автоматических сценариев

| Область | Минимальные проверки |
|---|---|
| CSV/seed | 126 строк; номера уникальны и равны 1–126; нет пустых полей; только 50/75/100/125/175/300; повторная инициализация не добавляет строки. |
| Тарифы | Все 6 высот × границы 1, 30, 31, 90, 91, 180, 181; один тариф применяется ко всему сроку; неизвестная высота/пробел диапазона дают понятную ошибку. |
| Даты аренды | Один день; обе даты включены; `end < start`; ноль/отрицательные дни; вычисление конца по дням; backend отклоняет подменённое число дней. |
| Статусы | При `as_of=2026-07-01`, порог 7: конец 2026-06-30 — overdue; 2026-07-01 и 2026-07-08 — expiring; 2026-07-09 — normal; свободная — free. |
| Штраф продления | Старый конец 2026-06-27: продление 27/28 июня — 0 дней; 29 июня — 1; ставка всегда диапазона 1–30. |
| Штраф закрытия | Конец 2026-06-27: закрытие 27 июня — 0; 28 июня — 1; 29 июня — 2. |
| Read-only | URI содержит `mode=ro`; запись и DDL отклоняются; соединение закрывается после результата и исключения. |
| Недоступная сеть | Нет общей папки/БД/прав; показано утверждённое сообщение; локальная БД не появляется. |
| Занятие | Успех; обязательные поля; занятая ячейка; два конкурентных запроса; DB `UNIQUE`; повторный `operation_id`; lock; rollback после искусственного сбоя. |
| Переходы | Нельзя занять занятую, продлить/закрыть свободную, повторно закрыть архивный договор или удалить историю. |
| Продление | Актив и renewal меняются вместе; своевременно/на следующий день/просрочено; повтор и rollback; старая история сохраняется. |
| Закрытие | Архивная вставка и удаление актива одним `COMMIT`; три вида закрытия; сбой до/после архивной вставки; повтор; ячейка освобождается только после успеха. |
| Конкуренция | Реальная вторая SQLite-сессия держит write lock; приложение ждёт настроенный срок, показывает понятную ошибку и не оставляет частичных данных. |
| Приватность | Общий API/HTML не содержат ФИО, ID и счёт; технические логи не содержат тестовые секретные маркеры; XSS-строки экранированы. |
| Документы | Неизвестный/отсутствующий плейсхолдер; обязательное поле; таблицы/колонтитулы; безопасное имя; path traversal; сбой публикации после `COMMIT`; реестра файлов нет. |
| Администратор | Стойкий хеш с солью; пароль не логируется; неверный пароль; пересекающиеся тарифы и неизвестный config запрещены; аудит изменений. |
| Бэкапы | Две копии и манифест; SQLite `quick_check`; контрольные суммы; временный неполный комплект не считается; ротация до 30; повреждение; отказ между копиями. |
| Восстановление | Не запускается автоматически; требует административный режим; сохраняет повреждённые файлы; восстанавливает обе базы из одного валидного комплекта. |
| Runtime | Только loopback; свободный порт; токен экземпляра; закрытие одного процесса не влияет на другой; обновление страницы не завершает процесс. |

## 3. Проверки этапа 0

Выполнено 12 июля 2026 года:

- CSV прочитан машинно: 126 строк, 126 уникальных номеров, диапазон 1–126, пропусков/дубликатов/пустых полей/недопустимых высот нет.
- Распределение высот: 50 мм — 45, 75 мм — 13, 100 мм — 56, 125 мм — 4, 175 мм — 5, 300 мм — 3.
- Корневые копии ТЗ, архитектуры, CSV и прототипа совпадают с каноническими файлами по SHA-256.
- Код и pytest-тесты ещё не существуют; утверждение об их прохождении не делается.

## 4. Ручная приёмка по этапам

1. После этапа 2 — внешний вид, понятность цветов, высот, фильтров и сетевой ошибки.
2. После этапа 9 — визуальная сверка каждого реального DOCX с утверждённым банковским шаблоном.
3. После этапа 12 — полный путь: запуск, поиск, расчёт, занятие, продление, закрытие, документ, бэкап и второй экземпляр.
4. До допуска в банк — тест на фактическом сетевом томе только с вымышленными данными и 1–3 компьютерами.
