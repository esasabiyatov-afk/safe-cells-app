# Модель данных

Документ задаёт логическую схему. Точный SQL реализован и протестирован на этапе 1. Единственная валюта — сом (`KGS`), дробные суммы не используются. Поля с техническим суффиксом `_minor` при `currency_scale = 0` содержат целое количество сомов.

## 1. Рабочая база `vault_cells.sqlite3`

### `schema_version`

| Поле | Тип | Правило |
|---|---|---|
| `version` | INTEGER | Положительное, одна текущая версия. |
| `applied_at` | TEXT | ISO-время со смещением. |

Текущая версия — 5. Переход 2→3 явно переименовывает ошибочное поле срока действия ID-карты в дату выдачи. Переход 3→4 добавляет `cell_blocks`, а переход 4→5 заменяет узкое банковское занятие универсальной ручной пометкой. Все миграции выполняются только явно, сразу для рабочей и архивной версий, после резервной копии и без фоновой миграции при запуске.

Миграции не запускаются молча при обычном старте. Перед изменением схемы требуется проверенный бэкап и административная процедура.

### `vault_defaults`

| Поле | Тип | Правило |
|---|---|---|
| `id` | INTEGER | `PRIMARY KEY`, всегда `1`. |
| `width_mm` | INTEGER | `NOT NULL`, больше 0; seed 220. |
| `depth_mm` | INTEGER | `NOT NULL`, больше 0; seed 330. |

### `cells`

| Поле | Тип | Правило |
|---|---|---|
| `number` | TEXT | `PRIMARY KEY`, непустой. |
| `height_mm` | INTEGER | `NOT NULL`, больше 0. Seed допускает 50, 75, 100, 125, 175, 300. |
| `width_mm` | INTEGER | `NULL` означает значение из `vault_defaults`; иначе больше 0. |
| `depth_mm` | INTEGER | Аналогично `width_mm`. |

Статус и клиентские данные в таблице не хранятся.

### `cell_blocks`

Хранит только занятость, которая не является активным клиентским договором.

| Поле | Тип | Правило |
|---|---|---|
| `cell_number` | TEXT | `PRIMARY KEY`, ссылка на `cells(number)`. |
| `block_kind` | TEXT | Только `lost_key` или `manual`. |
| `source_contract_id` | TEXT | Обязателен для `lost_key`, чтобы получить клиента из архива; для `manual` всегда `NULL`. |
| `occupation_label` | TEXT | Для `manual` обязательная нормализованная пометка длиной 1–80 символов; для `lost_key` всегда `NULL`. |
| `created_at` | TEXT | ISO-время со смещением. |
| `created_by` | TEXT | Полное имя выбранного сотрудника. |

Полное ФИО в таблице не дублируется. Для утерянного ключа оно читается из `contracts_archive` по `source_contract_id`. Два триггера запрещают одновременное существование `cell_blocks` и активного договора одной ячейки.

### `tariffs`

| Поле | Тип | Правило |
|---|---|---|
| `height_mm` | INTEGER | `NOT NULL`, больше 0. |
| `period_from_days` | INTEGER | `NOT NULL`, не меньше 1. |
| `period_to_days` | INTEGER | `NULL` для последнего диапазона; иначе не меньше начала. |
| `price_per_day_minor` | INTEGER | `NOT NULL`, неотрицательное. |
| `updated_at` | TEXT | ISO-время. |
| `updated_by` | TEXT | Полное имя выбранного сотрудника. |

Первичный ключ: (`height_mm`, `period_from_days`). Сервис дополнительно запрещает пробелы и пересечения диапазонов и требует ровно один подходящий тариф для каждого допустимого дня.

### `config`

| Поле | Тип | Правило |
|---|---|---|
| `key` | TEXT | `PRIMARY KEY`. |
| `value` | TEXT | `NOT NULL`; преобразуется и проверяется по белому списку ключей. |
| `updated_at` | TEXT | ISO-время. |
| `updated_by` | TEXT | Полное имя выбранного сотрудника. |

Обязательные ключи: `expiring_soon_days`, `deposit_amount_minor`, `currency_code`, `currency_scale`, `admin_access_mode`, `employees_json`. Режим доступа содержит только `password` или `acknowledgement`, не является секретом. `employees_json` содержит проверенный общий справочник с UUID, полным именем и признаком активности; выбранный для локального запуска сотрудник в БД не хранится. Секреты здесь не хранятся.

### `contracts`

Таблица содержит только активные договоры.

| Группа | Поля и основные правила |
|---|---|
| Идентификаторы | `contract_id TEXT PRIMARY KEY` (UUID), `cell_number TEXT NOT NULL UNIQUE REFERENCES cells(number)`. |
| Клиент | `client_full_name`, `id_card_number`, `id_card_issuer`, `id_card_issue_date`, `account_number` — обязательны; `extra_fields_json` зарезервирован для утверждённых дополнительных реквизитов шаблона. |
| Срок | `start_date`, `end_date` ISO-даты; `rent_days INTEGER >= 1`; backend проверяет включительную формулу. |
| Деньги | `price_per_day_minor`, `rent_price_minor`, `deposit_amount_minor` — целые неотрицательные значения; сохраняются неизменяемым финансовым снимком на момент открытия и не пересчитываются при изменении справочника тарифов. |
| Аудит | `created_at`, `created_by`, `updated_at`, `updated_by`; обязательны. |

Номер договора не хранится; дата выдачи ID-карты хранится в `id_card_issue_date` и используется в утверждённых DOCX. Внутренний UUID договора всегда уникален.

Для однократно перенесённого старого договора отсутствие финансовых или обязательных реквизитов отмечается утверждёнными служебными значениями в `extra_fields_json`. Если XLSX содержит паспортные данные, номер счёта или залог, фактические известные значения сохраняются в обычных полях договора и доступны для последующей сверки; служебное значение используется только для действительно отсутствующего поля. В утверждённом старом реестре столбец «Номер договора» является источником `account_number`, но отдельное поле номера договора в схему не возвращается. Серия и номер документа нормализуются без пробелов.

### `admin_credentials`

| Поле | Тип | Правило |
|---|---|---|
| `id` | INTEGER | Единственная строка `1`. |
| `password_hash` | TEXT | Стойкий хеш с солью, никогда не исходный пароль. |
| `changed_at` | TEXT | ISO-время. |

### `document_templates`

| Поле | Тип | Правило |
|---|---|---|
| `template_id` | TEXT | UUID, `PRIMARY KEY`. |
| `document_type` | TEXT | Событие комплекта: `opening`, `renewal` или `closing`; прочие разрешённые типы могут использоваться только для ручного формирования. |
| `display_name` | TEXT | Название для интерфейса. |
| `relative_file_name` | TEXT | Только безопасное имя внутри общей папки `templates`. |
| `required_placeholders_json` | TEXT | Проверенный JSON-массив; пустой массив означает готовый документ без заполнения. |
| `is_active` | INTEGER | 0 или 1. |
| `updated_at`, `updated_by` | TEXT | Аудит изменения. |

Файлы DOCX не хранятся в БД и не являются реестром созданных документов.

## 2. Архивная база `vault_archive.sqlite3`

### `schema_version`

Та же роль, что в рабочей базе; версии двух схем проверяются как совместимая пара.

### `contracts_archive`

Содержит полную неизменяемую копию полей активного договора и дополнительные поля:

| Поле | Правило |
|---|---|
| `contract_id` | `PRIMARY KEY`, тот же UUID. |
| `closed_at` | ISO-время фактической операции. |
| `close_date` | Банковская календарная дата закрытия. |
| `close_reason` | Значение из белого списка плюс необязательное безопасное пояснение. |
| `close_kind` | `early`, `on_time` или `overdue`. |
| `unused_days` | Неотрицательное целое. |
| `penalty_days` | Неотрицательное целое по формуле закрытия. |
| `penalty_rate_minor`, `penalty_amount_minor` | Фактические значения на момент закрытия. |
| `deposit_refund_minor` | Полный залог при обычном закрытии; `0` при причине «Потеря ключа». Произвольные удержания не рассчитываются. |
| `closed_by`, `operation_id` | Обязательны; `operation_id` уникален. |

Архивные договоры не удаляются через приложение.

### `renewals`

| Поле | Правило |
|---|---|
| `renewal_id` | UUID, `PRIMARY KEY`. |
| `contract_id`, `cell_number` | Снимок идентификаторов договора. |
| `old_end_date`, `renewal_date`, `new_start_date`, `new_end_date` | ISO-даты. |
| `renewal_days` | Включительная длительность, не меньше 1. |
| `price_per_day_minor`, `renewal_price_minor` | Фактическая стоимость по тарифу на момент конкретного продления; последующие изменения тарифов её не меняют. |
| `penalty_days`, `penalty_rate_minor`, `penalty_amount_minor` | Фактический штраф на момент конкретного продления; сохраняется неизменяемым снимком. |
| `created_at`, `created_by`, `operation_id` | Аудит; `operation_id` уникален. |

История продлений не удаляется и не изменяется.

### `log`

| Поле | Правило |
|---|---|
| `log_id` | UUID, `PRIMARY KEY`. |
| `operation_id` | `NOT NULL UNIQUE`, ключ проверки повторной операции. |
| `occurred_at`, `employee` | Время со смещением и полное имя выбранного сотрудника. |
| `action` | Разрешённый код действия. |
| `contract_id`, `cell_number` | Допускают `NULL` для общих настроек. |
| `changes_json` | Валидный JSON только с разрешёнными полями; считается бизнес-данными. |

Технические трассировки и исключения в эту таблицу не записываются. Для действий `cell.manual_occupied` и `cell.manual_released` в `changes_json` допускается только нормализованная `occupation_label`, чтобы общий журнал показывал её в колонке клиента. Это бизнес-история; технические логи и манифесты резервных комплектов это значение не копируют.

## 3. Инварианты

1. На одну ячейку приходится не более одного активного договора.
2. Свободность определяется одновременным отсутствием активного договора и строки `cell_blocks`.
3. В активной и архивной таблице один `contract_id` одновременно не существует после успешного закрытия.
4. Каждая подтверждённая запись имеет ровно один уникальный `operation_id` в аудите.
5. Даты и сохранённые дни согласованы; суммы равны проверенным целочисленным произведениям и суммам.
6. Тарифные диапазоны одной высоты не пересекаются и не имеют пробелов.
7. Удаление архивных договоров и продлений приложением не поддерживается.
8. Межбазовые инварианты проверяются сервисом внутри общей транзакции и интеграционными тестами, потому что SQLite не поддерживает внешние ключи между файлами.
9. `lost_key` всегда ссылается на архивный договор этой ячейки; `manual` не содержит клиента и срока, но содержит обязательную пометку.
10. Активный договор и отдельная блокировка одной ячейки взаимно исключаются сервисными проверками и триггерами БД.

## 4. Seed-данные

- `cells`: 126 уникальных строк из `data/cell_heights.csv`.
- `vault_defaults`: 220 × 330 мм.
- `tariffs`: 24 строки — 6 высот × 4 периода из ТЗ.
- `config.expiring_soon_days`: безопасное начальное значение 7 из визуального референса, редактируемое администратором.
- `config.currency_code`: `KGS`; выбора валюты в пользовательских формах нет.
- `config.currency_scale`: `0`; дробные суммы запрещены.
- `config.deposit_amount_minor`: `1500`; настройка редактируется администратором рядом с тарифами.
- `config.admin_access_mode`: начальное значение `acknowledgement`; при желании после создания любого непустого общего пароля можно выбрать `password`.
- `config.employees_json`: пустой общий справочник; первый сотрудник добавляется через настройки.
- `config.penalty_rate_mode`: `linked` для тарифа 1–30 дней либо `manual` для независимого набора.
- `config.penalty_manual_rates_json`: полный проверяемый набор ручных штрафных ставок по фактическим высотам; хранится даже при режиме `linked`.
