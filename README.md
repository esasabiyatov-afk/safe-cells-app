# Safe Cells — учёт банковских сейфовых ячеек

Локальное Flask-приложение без интернета. Каждый компьютер сотрудника запускает собственный локальный процесс, а рабочая и архивная SQLite-базы находятся в одной общей папке на сетевом диске.

Сотрудник в готовой версии будет нажимать только веб-ярлык «Сейфовые ячейки» на рабочем столе. Скрытая сборка и создание ярлыка относятся к этапу 12.

## Текущее состояние

Технически завершены этапы 0–11.5: от архитектуры и безопасной работы с двумя SQLite-базами до договорных операций, DOCX-комплектов, административных настроек, резервного восстановления и общего журнала ячеек. Этап 12 не начат.

## Требования для разработки

- Windows;
- Python 3.12 или новее;
- интернет нужен только разработчику для первоначальной установки зависимостей;
- само приложение не использует интернет.

## Подготовка окружения разработчика

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

## Локальная конфигурация

Скопируйте `config.example.json` в `config.local.json` и укажите существующую тестовую папку. `config.local.json` исключён из Git. Обычный запуск не создаёт папку или базы автоматически.

Пример только для локального теста:

```json
{
  "database_directory": "C:\\SafeCellsTestData",
  "working_database_name": "vault_cells.sqlite3",
  "archive_database_name": "vault_archive.sqlite3"
}
```

Не указывайте реальный банковский путь во время разработки.

## Явная инициализация тестовых баз

Команда выполняется только для заранее выбранной тестовой папки:

```powershell
.\.venv\Scripts\python.exe -m app.cli init-db --config config.local.json --confirm INITIALIZE
```

Повторный запуск команды не создаёт дубликаты и не перезаписывает изменённые тарифы. Если найден только один файл из пары, команда останавливается без создания второго.

## Технический запуск этапа 1

```powershell
.\.venv\Scripts\python.exe run.py --config config.local.json
```

Главный экран доступен по адресу `http://127.0.0.1:5000/`, техническая проверка — по адресу `http://127.0.0.1:5000/health`.

На главном экране реализованы точные высоты, четыре вычисляемых статуса, счётчики, поиск, фильтры и автоматическое обновление каждые 15 секунд. При потере доступа к базе старая сетка скрывается, чтобы её нельзя было принять за актуальные данные.

Нажатие на свободную ячейку открывает калькулятор. Можно задать дату начала и дату окончания либо количество дней. Обе даты включаются в срок, тариф выбирается для всего срока целиком. Единственная валюта — сом, дробных сумм нет, залог — 1500 сом и хранится в административной настройке рядом с тарифами.

Изменение тарифов применяется только к будущим расчётам. Ставка и сумма уже открытого договора не пересчитываются. При продлении используется действующий на тот момент тариф, а условия каждого дополнительного соглашения сохраняются в истории отдельным неизменяемым снимком.

После расчёта доступна форма договора. Запись выполняется только кнопкой «Подтвердить и занять»: backend заново проверяет поля, даты, тариф и свободность ячейки внутри короткой транзакции. Договор и обезличенная запись аудита сохраняются вместе. Повтор того же запроса не создаёт дубликат.

Карточка занятой ячейки сразу показывает только оперативные сведения. ФИО, ID-карта, счёт, номер договора и история не входят в общий API и запрашиваются отдельно только кнопкой «Показать данные». Запрос защищён временным токеном текущего запуска; после скрытия, закрытия карточки или сетевой ошибки персональные значения очищаются из DOM.

Кнопка «Журнал ячеек» открывает общую обезличенную историю занятия, продления, исправления данных и закрытия по всем ячейкам. Доступны фильтры по номеру, действию и датам; клиентские данные в журнал не выдаются. Маленькая шестерёнка в правом верхнем углу открывает шесть вкладок, включая резервные копии. Можно выбрать единый пароль отдела либо предупреждение без пароля. Если используется пароль, он хранится только как стойкий хеш с солью. При каждом запуске сотрудник обязательно выбирает своё имя из общего справочника; связи с Windows-учёткой нет. В карточках DOCX видно назначение, файл и поля; готовый документ без полей тоже разрешён. После операций и повторного формирования отдельное окно перечисляет созданные файлы в «Загрузках». Поля дней аренды и продления открываются пустыми, даты используют формат `ДД.ММ.ГГГГ` с четырёхзначным годом и последовательным Backspace, а формы закрываются только явными кнопками. Добавление новых ячеек в текущей версии отсутствует.

## Автоматические тесты

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты используют временные локальные папки и вымышленные данные. Они не обращаются к общей банковской базе.

## Важные ограничения

- WAL не используется.
- Обычный запуск не создаёт отсутствующую базу и не подменяет её локальной копией.
- Чтение выполняется через короткое соединение `mode=ro`.
- Подготовленное write-соединение использует `busy_timeout=15000`, DELETE journal, FULL synchronous и NORMAL locking.
- Просмотр и калькулятор используют короткие read-only соединения; запись открывается только после явного подтверждения.
- После каждой подтверждённой записи создаётся атомарно публикуемый комплект двух баз через SQLite Backup API с `quick_check`, манифестом и SHA-256; хранятся последние 30 комплектов. В настройках доступен просмотр состояния и контролируемое восстановление только после обнаруженного повреждения и закрытия других экземпляров.
- DOCX-механизм поддерживает утверждённые квадратные коды, включая первоначальную дату договора, данные конкретного продления и обе формы суммы залога. После подтверждённой операции автоматически формируются три файла при открытии, один при продлении и один при закрытии; все пять шаблонов заполняются с сохранением структуры и полей страницы.
