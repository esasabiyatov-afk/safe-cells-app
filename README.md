# Safe Cells — учёт банковских сейфовых ячеек

Локальное Flask-приложение без интернета. Каждый компьютер сотрудника запускает собственный локальный процесс, а рабочая и архивная SQLite-базы находятся в одной общей папке на сетевом диске.

Сотрудник нажимает только ярлык «Сейфовые ячейки» на рабочем столе. Он без консольного окна запускает локальный переносимый `safe-cells.exe` и открывает интерфейс в браузере по умолчанию.

## Текущее состояние

Этапы 0–12 технически завершены. Переносимая оконная сборка проверена без установленного Python, на свободном loopback-порту, полным рабочим циклом и тремя одновременными локальными экземплярами. До допуска в банк остаются ручная приёмка на фактическом тестовом SMB-томе с 1–3 компьютерами, проверка антивирусом и визуальная сверка утверждённых DOCX в Microsoft Word.

## Требования для разработки

- Windows;
- Python 3.12 или новее;
- интернет нужен только разработчику для первоначальной установки зависимостей;
- само приложение не использует интернет.

## Подготовка окружения разработчика

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

Для воспроизведения проверенной сборочной среды вместо файлов с диапазонами версий можно использовать `requirements-lock.txt`.

## Переносимая Windows-сборка

Python на компьютерах сотрудников не нужен. На компьютере сборки выполните:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_portable.ps1
.\.venv\Scripts\python.exe .\scripts\smoke_test_portable.py
```

Готовый неустанавливаемый комплект находится в `dist\safe-cells-portable`. Он содержит один `safe-cells.exe`, мастер выбора общей папки и сценарий создания ярлыка. Папки `build` и `dist` исключены из Git.

На рабочем компьютере комплект размещается в обычной локальной папке. Один раз запускается `configure-database.cmd`: сотрудник выбирает общую сетевую папку, а проверенный `config.json` создаётся автоматически. После этого один раз запускается `create-shortcut.cmd`; сотрудник использует созданный ярлык «Сейфовые ячейки». Подробный порядок и приёмочный лист находятся в `docs/DEPLOYMENT_GUIDE.md`.

## Локальная конфигурация

Скопируйте `config.example.json` в `config.local.json` и укажите существующую тестовую папку. `config.local.json` исключён из Git. Обычный запуск не создаёт папку или базы автоматически.

Пример только для локального теста:

```json
{
  "database_directory": "C:\\SafeCellsTestData",
  "working_database_name": "vault_cells.sqlite3",
  "archive_database_name": "vault_archive.sqlite3"
}
```

Не указывайте реальный банковский путь во время разработки.

## Явная инициализация тестовых баз

Команда выполняется только для заранее выбранной тестовой папки:

```powershell
.\.venv\Scripts\python.exe -m app.cli init-db --config config.local.json --confirm INITIALIZE
```

Повторный запуск команды не создаёт дубликаты и не перезаписывает изменённые тарифы. Если найден только один файл из пары, команда останавливается без создания второго.

## Технический запуск из исходников

```powershell
.\.venv\Scripts\python.exe run.py --config config.local.json
```

По умолчанию приложение автоматически занимает свободный локальный порт и открывает браузер. Для отладки можно явно добавить `--port 5000`; тогда главный экран будет доступен по адресу `http://127.0.0.1:5000/`, а техническая проверка — по адресу `http://127.0.0.1:5000/health`.

На главном экране реализованы точные высоты, четыре вычисляемых статуса, счётчики, поиск, фильтры и автоматическое обновление каждые 15 секунд. При потере доступа к базе старая сетка скрывается, чтобы её нельзя было принять за актуальные данные.

Нажатие на свободную ячейку открывает калькулятор. Можно задать дату начала и дату окончания либо количество дней. Обе даты включаются в срок, тариф выбирается для всего срока целиком. Единственная валюта — сом, дробных сумм нет, залог — 1500 сом и хранится в административной настройке рядом с тарифами.

Изменение тарифов применяется только к будущим расчётам. Ставка и сумма уже открытого договора не пересчитываются. При продлении используется действующий на тот момент тариф, а условия каждого дополнительного соглашения сохраняются в истории отдельным неизменяемым снимком.

После расчёта доступна форма договора. Запись выполняется только кнопкой «Подтвердить и занять»: backend заново проверяет поля, даты, тариф и свободность ячейки внутри короткой транзакции. Договор и обезличенная запись аудита сохраняются вместе. Повтор того же запроса не создаёт дубликат.

Карточка занятой ячейки сразу показывает только оперативные сведения. ФИО, ID-карта, счёт, номер договора и история не входят в общий API и запрашиваются отдельно только кнопкой «Показать данные». Запрос защищён временным токеном текущего запуска; после скрытия, закрытия карточки или сетевой ошибки персональные значения очищаются из DOM.

Кнопка «Журнал ячеек» открывает в новой вкладке отдельную страницу общей истории открытия, продления и закрытия по всем ячейкам; главный экран остаётся открытым. В каждой строке видно ФИО клиента либо ручную пометку занятия; исправления данных, ID-карта и номер счёта не показываются. Доступны фильтры по номеру, действию, клиенту/пометке, сотруднику и датам, а текущий отбор выгружается в настоящий Excel-файл `.xlsx` с колонками «Дата и время», «Клиент», «Ячейка», «Действие», «Сведения», «Сотрудник». Маленькая шестерёнка в правом верхнем углу открывает вкладки настроек, включая резервные копии. Новая база использует предупреждение без пароля; при желании можно включить любой непустой общий пароль, который хранится только как стойкий хеш с солью. При каждом запуске сотрудник обязательно выбирает своё имя из общего справочника; связи с Windows-учёткой нет. После выбора заявления АБС DOCX разрешённые поля автоматически подставляются в форму, а серия и номер документа объединяются без пробелов; файл не сохраняется. В карточках DOCX видно назначение, файл и поля; готовый документ без полей тоже разрешён. После операций и повторного формирования отдельное окно показывает новые заполненные копии с кнопками «Скачать»; исходные шаблоны не изменяются, а backend не записывает файлы скрыто в Windows «Загрузки». Словесные даты в DOCX используют двузначный день: `03 сентября`, `03-сентябрь` или `«03» сентября`, а однозначный номер ячейки печатается с ведущим нулём: `02`. Поля дней аренды и продления открываются пустыми, даты используют формат `ДД.ММ.ГГГГ` с четырёхзначным годом и последовательным Backspace, а формы закрываются только явными кнопками. Добавление новых ячеек в текущей версии отсутствует.

## Автоматические тесты

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты используют временные локальные папки и вымышленные данные. Они не обращаются к общей банковской базе. Текущий полный строгий результат: `309 passed`.

## Важные ограничения

- WAL не используется.
- Обычный запуск не создаёт отсутствующую базу и не подменяет её локальной копией.
- Чтение выполняется через короткое соединение `mode=ro`.
- Подготовленное write-соединение использует `busy_timeout=15000`, DELETE journal, FULL synchronous и NORMAL locking.
- Просмотр и калькулятор используют короткие read-only соединения; запись открывается только после явного подтверждения.
- После каждой подтверждённой записи создаётся атомарно публикуемый комплект двух баз через SQLite Backup API с `quick_check`, манифестом и SHA-256; хранятся последние 30 комплектов. В настройках доступен просмотр состояния и контролируемое восстановление только после обнаруженного повреждения и закрытия других экземпляров.
- DOCX-механизм поддерживает утверждённые квадратные коды, включая первоначальную дату договора, данные конкретного продления и обе формы суммы залога. После подтверждённой операции автоматически формируются четыре файла при открытии, один при продлении и один при закрытии; комплект из шести шаблонов включает бирку на конверт и заполняется без изменения исходников.
