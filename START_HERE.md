# Полная инструкция: как разработать приложение сейфовых ячеек через Codex

## Что находится в комплекте

- `AGENTS.md` — постоянные правила, которые Codex читает перед задачами.
- `docs/tz-seyfy-novy-proekt.md` — полное функциональное ТЗ.
- `docs/APPROVED_ARCHITECTURE.md` — утверждённые исправления по сетевой SQLite-базе.
- `data/cell_heights.csv` — реальные номера и высоты 126 ячеек.
- `reference/seyfy-prototip.html` — визуальный референс.
- `PROMPT_01_ARCHITECTURE.md` — первый запрос: анализ и план без кода.
- `PROMPT_02_MILESTONE_1.md` — первый этап реализации.
- `PROMPT_STAGE_TEMPLATE.md` — шаблон для последующих этапов.
- `REVIEW_PROMPT.md` — проверка изменений.
- `CODEX_WORKFLOW.md` — краткий рабочий процесс.

## Главная архитектура

Каждый сотрудник запускает собственный `safe-cells.exe`. Приложение работает локально на его компьютере, а общие базы `vault_cells.sqlite3` и `vault_archive.sqlite3` находятся на сетевом диске банка.

Просмотр данных:

```text
открыть SQLite в mode=ro → выполнить SELECT → закрыть соединение
```

Изменение данных:

```text
нажатие подтверждающей кнопки → открыть read/write → BEGIN IMMEDIATE
→ повторно проверить данные → изменить → COMMIT/ROLLBACK → закрыть
```

Обычно приложением пользуется один сотрудник; редко одновременно до трёх. WAL не используется.

## Пошаговая работа

### Шаг 1. Распакуйте комплект

Создайте папку, например:

```text
C:\Projects\safe-cells-app
```

Распакуйте туда весь комплект, сохранив структуру папок.

### Шаг 2. Откройте папку в Codex

Откройте именно корневую папку проекта. Codex должен одновременно видеть `AGENTS.md`, ТЗ, CSV и HTML-референс.

### Шаг 3. Создайте Git-точку возврата

Отправьте Codex:

```text
Инициализируй Git-репозиторий в текущей папке и создай первый commit исходных требований. Пока не пиши код приложения.
```

### Шаг 4. Получите архитектурный план

Отправьте всё содержимое `PROMPT_01_ARCHITECTURE.md`.

Codex должен создать только документацию. Он не должен устанавливать Flask или писать приложение на этом шаге.

### Шаг 5. Проверьте план

Проверьте, что он сохранил утверждённую архитектуру сетевого диска и разделил работу на небольшие этапы.

Особенно проверьте:

- read-only соединения для просмотра;
- write-соединение только по подтверждённой операции;
- `BEGIN IMMEDIATE` и `busy_timeout`;
- повторную проверку ячейки перед сохранением;
- уникальное ограничение активной аренды;
- `ATTACH DATABASE` для закрытия договора;
- запрет WAL;
- отсутствие локальной пустой базы при ошибке сети.

### Шаг 6. Запустите первый этап разработки

После утверждения документов отправьте `PROMPT_02_MILESTONE_1.md`.

Проверьте главный экран, импорт 126 ячеек и тесты. Не просите пока оформлять договоры.

### Шаг 7. Реализуйте этапы по одному

Используйте `PROMPT_STAGE_TEMPLATE.md`. Укажите только один этап из `docs/IMPLEMENTATION_PLAN.md`.

### Шаг 8. Проверяйте каждый этап

После ручной проверки и исправлений запустите review с текстом `REVIEW_PROMPT.md`. После успешного результата сделайте Git commit.

## Рекомендуемая последовательность этапов

1. Документация и архитектура.
2. Каркас, конфигурация, две БД и seed-данные.
3. Read-only главный экран.
4. Калькулятор аренды.
5. Оформление активного договора.
6. Карточка занятой ячейки.
7. Продление и штраф.
8. Закрытие и перенос в архив.
9. DOCX-шаблоны.
10. Административные настройки.
11. Бэкапы и восстановление.
12. PyInstaller и проверка на 1–3 компьютерах.

## Правило для любых запросов

Не просите Codex сделать всё приложение одной командой. Один этап должен иметь конкретный результат, тесты и ручную проверку.
